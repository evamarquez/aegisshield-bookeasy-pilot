# Working Plan

## Phase 0 — Frame the case

**Purpose:** Establish a credible fictional company, product, problem statement, and decision context.

**Outputs:**

- Project brief.
- Role map.
- Initial assumptions and open questions.

## Phase 1 — Understand the current state

**Purpose:** Build an inventory before proposing modernization work.

**Planned outputs:**

- Product and service map.
- Component inventory.
- Dependency and integration map.
- Ownership map.
- Current-state risks.

## Phase 2 — Assess and prioritize

**Purpose:** Decide what should be upgraded first and why.

**Planned outputs:**

- Technical debt assessment.
- Risk scoring model.
- Upgrade/replace/retire decision matrix.
- Prioritized backlog.
- Decision log.

## Phase 3 — Plan delivery

**Purpose:** Turn the assessment into an executable modernization roadmap.

**Planned outputs:**

- Work breakdown structure.
- Milestone plan.
- Dependency map.
- RAID log.
- Testing and release strategy.
- Stakeholder communication plan.

## Phase 4 — Define the first increment

**Purpose:** Design a realistic first release without pretending the entire modernization is complete.

**Planned outputs:**

- First-release scope.
- Acceptance criteria.
- Release-readiness checklist.
- Rollback and validation plan.
- Status update for leadership.

## Phase 5 — Prepare the website handoff

**Purpose:** Convert the completed case into a concise portfolio presentation.

**Planned outputs:**

- One-paragraph case summary.
- Role and responsibilities summary.
- Selected artifacts.
- Outcome section clearly labeled as simulated.
- Link to the full GitHub documentation.

## Working rule

We will complete one phase at a time. We will not jump directly to a polished website card before the underlying case and decisions are documented.

## Current progress

- Case frame and sponsor handoff: documented.
- Project brief and BookEasy pilot boundaries: documented.
- Roles, stakeholders, and communication approach: documented.
- Current-state inventory and dependencies: documented.
- Next: prioritize risks and turn them into an executable delivery plan.
